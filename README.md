# react-native-unilitix

Official React Native SDK for [Unilitix](https://unilitix.com) —
African-first mobile UX analytics.

[![npm version](https://img.shields.io/npm/v/react-native-unilitix.svg)](https://www.npmjs.com/package/react-native-unilitix)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

## Install

```bash
npm install react-native-unilitix
# or
yarn add react-native-unilitix
```

Then `cd ios && pod install` and rebuild the app. The SDK works on the New
Architecture (TurboModule + Fabric components, generated by codegen) and on
the legacy bridge; nothing to configure.

**Expo:** add the config plugin and use a development build (`expo
prebuild` / EAS Build). In Expo Go the native module is absent and every
call is a no-op.

```json
{ "expo": { "plugins": ["react-native-unilitix"] } }
```

See [Expo](#expo) for the plugin's options.

## Quick start

```tsx
import Unilitix from 'react-native-unilitix';
import { useEffect } from 'react';

export default function App() {
  useEffect(() => {
    // Logs only in development builds. Installs the JS crash handler too.
    Unilitix.init('YOUR_API_KEY', { debug: __DEV__ });
  }, []);
}
```

The SDK never throws or rejects into your app: `init()` and every other
call resolve even when the native side fails (dev builds log a
`[Unilitix] … failed` warning; `Unilitix.isInitialized` tells you whether
init succeeded, and a failed `init()` can be called again).

Get your API key at [app.unilitix.com](https://app.unilitix.com)
→ Settings → Apps → Create App.

## Track events

```ts
Unilitix.track('purchase_completed', {
  amount: 5000,
  currency: 'NGN',
});
```

Properties (and `identify` traits) are cleaned before they reach native
code, by the contract's rules: functions, symbols and `undefined` are
dropped, `NaN`/`Infinity` become `null`, circular references become
`'[Circular]'`, nesting deeper than 5 levels becomes `'[Truncated]'`,
strings (and event names, screen names, user ids) are cut at 1024 UTF-16
units without splitting an emoji, and objects/arrays at 100 entries.

## Identify users

```ts
// After login
Unilitix.identify('user_123', {
  name: 'Tosin',
  plan: 'pro',
  country: 'Nigeria',
});

// After logout
Unilitix.reset();
```

## Screen tracking

React Navigation: pass the container ref to the hook. It tracks the
**first screen** once the container is ready (`onStateChange` never reports
it) and then every focused-route change. Only `route.name` is sent, never
params.

```tsx
import { NavigationContainer, useNavigationContainerRef } from '@react-navigation/native';
import { useUnilitixNavigationTracking } from 'react-native-unilitix';

export default function App() {
  const navigationRef = useNavigationContainerRef();
  const onReady = useUnilitixNavigationTracking(navigationRef);
  return (
    <NavigationContainer ref={navigationRef} onReady={onReady}>
      {/* your app */}
    </NavigationContainer>
  );
}
```

Or wrap the container once (your own `ref`, `onReady` and `onStateChange`
still work):

```tsx
import { withUnilitixNavigation } from 'react-native-unilitix';
const TrackedNavigationContainer = withUnilitixNavigation(NavigationContainer);
```

Expo Router: call the hook in the root layout with `useSegments()`. Screens
are named by route pattern (`/users/[id]`, layout groups left out), so ids
in the URL never leave the device.

```tsx
import { Stack, useSegments } from 'expo-router';
import { useUnilitixExpoRouterTracking } from 'react-native-unilitix';

export default function RootLayout() {
  useUnilitixExpoRouterTracking(useSegments());
  return <Stack />;
}
```

`Unilitix.screen(name)` works anywhere. A screen equal to the current
screen of the session is dropped (contract rule), so wiring several of
these is harmless; the first screen of a new session is always sent.
`createUnilitixNavigationListener()` (for `onStateChange`) is still
available but misses the first screen.

> **Note:** The `autoTrackScreens` config option has no effect in React Native — all screens run inside a single Android `Activity` / iOS root view controller, so native lifecycle callbacks cannot see JS navigation. Use the helpers above.

## Crash tracking

Native (Kotlin/Java) crashes and JS errors are both captured once `init()`
has run — no extra wiring:

- An uncaught JS error is reported as a `CRASH` with the last 50
  breadcrumbs (taps, screens, custom events, your own `addBreadcrumb`).
  The report is persisted on-device (bounded to 2 s) before React Native's
  own handler runs, so a fatal error still reaches the dashboard.
- An unhandled promise rejection is reported as a non-fatal `EXCEPTION`
  (Hermes; on JSC use `captureException` in your `.catch`). Hermes allows a
  single rejection tracker and cannot tell anyone which one is installed, so
  Unilitix chains what it can: a tracker installed **after** `init()` keeps
  receiving every callback (Unilitix's stays in place), and one installed
  **before** is chained when you pass it as `rejectionTracker`. React
  Native's own dev-mode "Possible unhandled promise rejection" warning is
  still logged in `__DEV__`. Pass `trackUnhandledRejections: false` if
  another library must own the tracker outright.
- Your previous global error handler (React Native's red box / process exit,
  or another SDK's) always runs, with the original `isFatal`, even if
  reporting fails.
- On iOS, an uncaught Objective-C exception is reported as a `CRASH` with
  its stack, and a fatal signal in native code (SIGSEGV, SIGBUS, SIGABRT,
  SIGILL, SIGFPE, SIGTRAP) is reported on the next launch against the
  session that crashed (`exceptionType` `SIGNAL`, e.g.
  `Fatal signal 11 (SIGSEGV)`). A fatal JS error is reported once: the
  native exception and abort React Native raise after it are not reported
  again.
- Every report carries the contract fingerprint (computed in JS for JS
  errors, so iOS and Android group them the same way) and, for JS errors,
  `jsBundleId`, `release` (app version) and `dist` (build number), so stack
  traces are symbolicated with the right source map — see
  [Source maps](#source-maps).

```ts
try {
  await pay(card);
} catch (e) {
  Unilitix.captureException(e); // non-fatal EXCEPTION
}

Unilitix.addBreadcrumb('checkout started', 'flow');
```

Pass `installJsCrashHandler: false` to `init()` and call
`setupUnilitixCrashHandler()` yourself if you need to order it with another
error-reporting SDK; handlers installed before Unilitix still run.

## Masking in session replay

Wrap content that must never appear in replay, whatever the masking options
say (balances, card numbers, documents, QR codes), in `<UnilitixMask>`; wrap
content that is safe and needed to understand the screen in
`<UnilitixUnmask>` to show it even with `maskAllText` / `maskImages`.

```tsx
import { UnilitixMask, UnilitixUnmask } from 'react-native-unilitix';

<UnilitixUnmask>
  <Text>Transfer money</Text>
</UnilitixUnmask>
<UnilitixMask>
  <Text>{balance}</Text>
</UnilitixMask>
```

Both take `View` props. They are native views the replay cores honour
(iOS `unilitixPrivate` / `unilitixUnmasked`, Android `@UnilitixPrivate` /
`Unilitix.unmask(view)`), on Fabric and on the legacy renderer. Text inputs
stay masked inside `<UnilitixUnmask>`, and `<UnilitixUnmask>` never reveals
anything inside a `<UnilitixMask>`. On web and in Expo Go they render a
plain `View`.

## Source maps

Release builds ship minified (and on Hermes, compiled) JS, so JS stack
traces need the bundle's source map. Every JS error carries
`metadata.jsBundleId`, `release` and `dist`; upload the map under the same
ids with `unilitix-cli` (the tool that also uploads ProGuard mappings and
dSYMs) and the dashboard shows your original files and lines.

1. **Stamp the bundle with an id** (recommended; without it the id is the
   bundle file name, `index.android.bundle` / `main.jsbundle`, which is
   only unique per app version and build):

   ```js
   // metro.config.js
   const { withUnilitixConfig } = require('react-native-unilitix/metro');
   module.exports = withUnilitixConfig(config); // config = your current export
   ```

   Each release build gets a fresh id (or `$UNILITIX_BUNDLE_ID` if set). It
   is added on the line that starts the app, so source map positions do not
   move, and the upload step reads it back from the bundle (plain JS or
   Hermes bytecode).

2. **Upload in the build.** Set `UNILITIX_API_KEY` in the build environment
   (CI secret) and put `unilitix-cli` on `PATH` (or set `UNILITIX_CLI`).
   Debug builds are skipped. A missing key/CLI or a failed upload is a
   warning; set `UNILITIX_SOURCEMAPS_STRICT=1` to fail the build instead,
   `UNILITIX_SOURCEMAPS_DISABLED=1` to skip.

   - **Android** — in `android/app/build.gradle`, after
     `apply plugin: "com.facebook.react"`:

     ```groovy
     apply from: new File(["node", "--print", "require.resolve('react-native-unilitix/package.json')"]
         .execute(null, rootDir).text.trim(), "../android/unilitix-sourcemaps.gradle")
     ```

     Every release variant gets an `uploadUnilitixSourcemaps<Variant>` task
     that runs after React Native bundles it, with the final (Hermes-composed)
     map and the variant's `versionName` / `versionCode`.

   - **iOS** — make the bundle phase write the map by adding to
     `ios/.xcode.env`:

     ```sh
     export SOURCEMAP_FILE="$DERIVED_FILE_DIR/main.jsbundle.map"
     ```

     then add a Run Script phase **after** "Bundle React Native code and
     images":

     ```sh
     /bin/bash "$("${NODE_BINARY:-node}" --print "require('path').dirname(require.resolve('react-native-unilitix/package.json')) + '/scripts/upload-sourcemaps.sh'")"
     ```

     It uploads with `CFBundleShortVersionString` / `CFBundleVersion` of the
     built app. With Xcode's user script sandboxing on, list the bundle and
     map as the phase's input files (or turn sandboxing off for the target,
     as the React Native template does).

   - **Expo** — the config plugin adds both steps; add the Metro wrapper
     yourself (`expo/metro-config`'s config works the same way).

3. **Over-the-air updates** (EAS Update, CodePush): the JS changes without a
   new build, so pass the update's ids to `init` and upload its map with
   the same values:

   ```ts
   Unilitix.init(KEY, { jsBundleId: Updates.updateId ?? undefined, release: '2.3.0-ota.4' });
   ```

   ```sh
   unilitix-cli upload-sourcemap --platform android --app-version 2.3.0-ota.4 --build 230 \
     --bundle-id "$UPDATE_ID" --sourcemap <the update's .map>
   ```

By hand (any build): `node node_modules/react-native-unilitix/scripts/unilitix-sourcemaps.js upload --platform android --bundle <bundle> --sourcemap <map> --app-version <v> --build <b>`
(`bundle-id <bundle>` prints the id a bundle carries).

## Expo

`"plugins": ["react-native-unilitix"]` in `app.json` (development builds
and EAS Build; Expo Go = no-op, see above). Options:

```json
["react-native-unilitix", { "uploadSourceMaps": true, "cellularGeneration": false }]
```

- Android: applies the source-map Gradle hook and makes sure the manifest
  has `INTERNET` and `ACCESS_NETWORK_STATE`. `cellularGeneration: true` also
  requests `READ_PHONE_STATE` so cellular events report 5G/4G/3G/2G instead
  of `CELLULAR` (a runtime permission your app must ask for).
- iOS: makes the bundle phase write `main.jsbundle.map` and adds the
  "Upload Unilitix source maps" phase. No Info.plist keys are needed.
- `uploadSourceMaps: false` leaves the build untouched.

## Verify your integration

In debug mode, after `init()` resolves you will see in Metro console:

```
[Unilitix] ✅ SDK initialized
[Unilitix] ✅ Session started
[Unilitix] ⚠️ No screen events detected. Did you add
useUnilitixNavigationTracking(navigationRef)?
```

The `⚠️` warning only appears if no screen is tracked within 5 seconds of init. Wire one of the [screen tracking](#screen-tracking) helpers to suppress it. Silent in production builds.

## Configuration

```ts
await Unilitix.init('YOUR_API_KEY', {
  // Behaviour
  debug: __DEV__,
  autoTrackScreens: true,
  autoTrackTaps: true,
  autoTrackCrashes: true,
  autoTrackRageTaps: true,
  trackUnhandledRejections: true, // Hermes; see Crash tracking
  // Source maps (defaults: injected bundle id / app version / build number)
  jsBundleId: undefined,
  release: undefined,
  dist: undefined,
  // Privacy
  consent: 'granted',           // 'denied' collects nothing; see below
  maskInputs: true,
  maskAllText: true,            // iOS; applied on Android once the library exposes it
  maskImages: false,
  captureSnapshots: true,       // session replay DOM snapshots
  captureScreenshots: true,     // session replay screenshots
  uploadScreenshotsOnWifiOnly: true,
  replaySampleRate: 1.0,        // fraction of sessions with replay
  // Performance
  flushIntervalSeconds: 30,
  flushBatchSize: 100,
  maxOfflineEvents: 1000,
  sessionTimeoutSeconds: 1800,
});
```

`init()` is memoised and calls made before it resolves (`track`, `screen`,
`identify`, …) are queued (up to 200; the oldest is dropped first) and
replayed in order, so you can track from the first render. `Unilitix.isAvailable` is `false` in Expo Go (or when the
native module is not linked), where `init()` resolves, every call is a
no-op, and development builds log one warning.

## Privacy

```ts
Unilitix.setConsent('denied');   // stop tracking (same as optOut)
Unilitix.setConsent('granted');  // resume tracking (same as optIn)
Unilitix.reset();                // clear user identity
```

Apps that must ask first (NDPR, GDPR) start with `consent: 'pending'`:
events and replay are kept on the device and nothing is uploaded until
`setConsent('granted')` sends them, or `setConsent('denied')` deletes them.
The decision is persisted and wins over `consent` on later launches. This
works the same on Android and iOS. A `setConsent` call made before `init()`
is kept and wins over the `consent` option.

On iOS the pod ships a privacy manifest (`PrivacyInfo.xcprivacy`, in the
`unilitix_privacy` resource bundle) declaring the required-reason APIs the
SDK uses (UserDefaults `CA92.1`, system boot time `35F9.1`, file timestamps
`C617.1`), no tracking, and the data types it collects. They are declared
as linked to the user because `identify()` attaches your user id to the
session; Xcode includes them in your app's privacy report.

## Session control

```ts
// Manually start a new session
await Unilitix.startSession();

// End the current session
await Unilitix.endSession();

// Force upload all queued events immediately
await Unilitix.flush();
```

## Contract conformance

The SDK follows the shared Unilitix SDK contract (1.4.0). The JS layer runs
the contract's behaviour fixtures in Jest against a model of the native
core and asserts the exact native calls; [COVERAGE.md](COVERAGE.md) lists
which cases run here and which the Android / iOS cores own.

## iOS internals

The iOS side embeds [UnilitixCore](https://github.com/Unilitix-hq/unilitix-ios),
the native Unilitix iOS SDK. Its Swift sources are vendored into
`ios/UnilitixCore/` so the pod builds with any React Native version and no
extra dependency; `ios/UnilitixBridge.swift` adapts it to the JS bridge.
After changing UnilitixCore, refresh the copy with:

```sh
yarn ios:core   # scripts/sync-ios-core.sh ../unilitix-ios/UnilitixCore
```
